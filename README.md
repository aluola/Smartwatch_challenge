# 智音随行 - 智能手表音乐推荐应用

## 📖 项目简介

智音随行是一款基于 Uni-app 框架开发的智能手表音乐推荐应用。通过收集用户的个人信息和运动偏好，结合智能手表的实时传感器数据（心率、血氧、步数等），使用强化学习算法为用户推荐个性化的音乐。

## 🛠️ 技术栈

- **框架**: Vue 3 + Uni-app
- **UI 样式**: SCSS
- **状态管理**: Vue 3 Composition API (ref, reactive, computed)
- **本地存储**: uni.storage
- **蓝牙通信**: uni.BLE API
- **音频播放**: uni.createInnerAudioContext
- **HTTP 通信**: uni.request

## ✨ 主要功能

### 1. 初始化问卷系统

首次启动应用时，用户需要完成 6 步问卷：

1. **年龄**: 输入年龄信息
2. **性别**: 选择男性或女性
3. **身高体重**: 输入身高（cm）和体重（kg），自动计算 BMI
4. **运动频率**: 选择运动频率（几乎不运动、偶尔运动、规律健身、专业训练）
5. **运动类型**: 选择主要运动类型（跑步、骑行、力量训练、HIIT、瑜伽/拉伸）
6. **音乐流派**: 选择喜欢的音乐流派（可多选：Pop、EDM、Hip-Hop、Rock、Classical）

**特点**:
- 问卷完成后，用户信息会永久保存到本地存储
- 已完成问卷的用户再次启动应用时自动跳过问卷流程
- 问卷完成后自动上传用户信息到服务器（flag=0）

### 2. 蓝牙连接管理

**功能**:
- 蓝牙设备扫描和连接
- 自动保存已连接的设备信息
- 应用启动时自动尝试重连上次连接的设备
- 实时显示连接状态和设备名称
- 支持断开连接

**存储机制**:
- 使用 `bluetoothStorage.js` 管理设备信息
- 存储设备 ID、设备名称、连接时间戳

### 3. 传感器数据接收与显示

通过蓝牙接收智能手表发送的传感器数据：

**支持的数据类型**:
- `HEARTRATE:数值` - 心率（BPM）
- `SPO2:数值` - 血氧饱和度（%）
- `STEPSSTEPS:数值` - 步数
- `TEMPERATURE:数值` - 温度（°C）
- `TIME:时间字符串` - 手表当前时间

**实时计算**:
- **步频（Cadence）**: 根据最近 5 秒内的步数变化自动计算步频（步/分钟）

**显示界面**:
- 实时数据显示卡片
- 数据通信日志列表（记录所有接收/发送的数据）
- 手表当前时间显示模块

### 4. 音乐播放功能

**音乐管理**:
- 默认播放歌曲: `010377.mp3`（位于 `/static/music_new/music/`）
- 支持播放 8000+ 首歌曲（歌曲命名格式: `六位数字.mp3`）
- 歌曲列表通过 `music_list.json` 文件加载

**播放控制**:
- 播放/暂停
- 上一首/下一首（循环播放）
- 喜欢/不喜欢按钮（❤️/🤍）
- 实时显示当前播放歌曲名称
- 自动记录音乐播放时间

**远程控制**:
- 支持通过蓝牙接收手表的音乐控制指令：
  - `MUSIC:PLAY` - 播放
  - `MUSIC:PAUSE` - 暂停
  - `MUSIC:PREV` - 上一首
  - `MUSIC:NEXT` - 下一首

**服务器推荐**:
- 接收服务器通过强化学习推荐的歌曲
- 自动切换播放推荐的歌曲
- 推荐的歌曲会被加入到播放列表中

### 5. 服务器通信

**通信协议**:
- **服务器地址**: `http://47.93.210.224/calculate`
- **通信方式**: POST 请求，JSON 格式
- **ACK 机制**: 先发送标志位（flag），等待服务器返回 "yes" 后发送实际数据

**数据类型**:

1. **初始化信息（flag=0）**:
   - 用户年龄、性别、身高、体重、BMI
   - 运动频率、运动类型、音乐流派

2. **状态信息（flag=1）**:
   - 心率、血氧、步数、步频、温度
   - 当前歌曲名称、音乐播放时间、是否喜欢

**数据格式**:
- 上传格式: `{变量名: "变量名：变量值"}`
- 示例: `{heartRate: "heartRate：72", spo2: "spo2：98"}`

**触发时机**:
- 初始化信息: 问卷完成后自动上传
- 状态信息: 
  - 用户切歌时（上一首/下一首）
  - 通过手表控制切歌时

**服务器响应**:
- 服务器可能返回推荐的歌曲名（如: `"069825.mp3"`）
- 应用自动解析并播放推荐的歌曲

### 6. 数据存储

**本地存储**:
- 用户资料: `user_profile_data`
- 问卷完成状态: `questionnaire_completed`
- 蓝牙设备信息: `last_connected_bluetooth_device`

## 📱 使用说明

### 首次使用

1. 启动应用后，自动进入欢迎页面
2. 完成 6 步初始化问卷
3. 问卷完成后自动跳转到主页面
4. 点击"扫描设备"按钮搜索智能手表
5. 选择要连接的设备进行连接
6. 连接成功后，应用会自动加载并播放默认歌曲

### 日常使用

1. 启动应用后，如果是已连接过的设备，会自动尝试重连
2. 连接成功后，实时显示传感器数据
3. 可以通过界面按钮或手表按钮控制音乐播放
4. 切歌时会自动上传当前状态到服务器，并接收推荐歌曲

### 音乐控制

**界面控制**:
- 点击"播放/暂停"按钮控制播放状态
- 点击"«"/"»"按钮切换上一首/下一首
- 点击"❤️"按钮标记喜欢/不喜欢当前歌曲

**手表控制**:
- 手表发送 `MUSIC:PLAY` 指令播放音乐
- 手表发送 `MUSIC:PAUSE` 指令暂停音乐
- 手表发送 `MUSIC:PREV` 指令播放上一首
- 手表发送 `MUSIC:NEXT` 指令播放下一首

## 🔌 API 接口

### 工具函数 API

#### `utils/userData.js`

- `getUserProfile()` - 获取用户完整资料
- `saveUserProfile(profile)` - 保存用户资料
- `updateUserProfile(updates)` - 更新用户资料的部分字段
- `isQuestionnaireCompleted()` - 检查问卷是否已完成
- `markQuestionnaireCompleted()` - 标记问卷已完成
- `resetUserData()` - 重置用户数据（用于测试）
- `calculateBMI(height, weight)` - 计算 BMI
- `getUserField(fieldName, defaultValue)` - 获取用户资料字段

#### `utils/serverApi.js`

- `sendWithAck(flag, data)` - 发送带 ACK 确认的数据
- `uploadInitialInfo(initialData)` - 上传初始化信息（flag=0）
- `uploadStatusInfo(statusData)` - 上传状态信息（flag=1）
- `formatDataForLog(data)` - 格式化数据为字符串（用于控制台打印）

#### `utils/bluetoothStorage.js`

- `saveConnectedDevice(device)` - 保存已连接的蓝牙设备信息
- `getLastConnectedDevice()` - 获取上次连接的蓝牙设备信息
- `clearSavedDevice()` - 清除保存的蓝牙设备信息

## 🚀 开发说明

### 运行项目

1. 使用 HBuilderX 打开项目
2. 运行到 App-Plus（Android/iOS）或 H5 浏览器
3. 注意：H5 平台某些功能（如蓝牙）可能受限

### 平台差异处理

项目使用条件编译处理平台差异：

- `#ifdef APP-PLUS` - App 端专用代码
- `#ifdef H5` - H5 端专用代码

例如，音乐列表加载在 App 端使用文件系统 API，在 H5 端使用 HTTP 请求。

### 数据流图

```
用户填写问卷 → 保存到本地存储 → 上传到服务器（flag=0）
                                           ↓
蓝牙接收传感器数据 → 解析数据 → 显示在界面 → 切歌时上传状态（flag=1）
                                                      ↓
                                         服务器返回推荐歌曲 → 自动播放
```

## 📝 注意事项

1. **蓝牙权限**: 首次使用时需要授予蓝牙和位置权限（Android）
2. **音乐文件**: 确保 `static/music_new/music/` 目录下有音乐文件
3. **服务器连接**: 确保服务器地址可访问，网络连接正常
4. **数据格式**: 手表发送的数据必须严格按照格式（如 `HEARTRATE:72`）
5. **步数变量**: 手表的步数变量名为 `stepssteps`（不是 `steps`）
